## Word、Excel 在手机上直接显示（2026-10-28，未发布）

用户 10-28 看了 iPhone 上转成 PDF 的 Office 预览，问能不能不转换；iPhone 0.5.5 改成用系统自带的快速查看显示原文件。安卓系统没有这样的组件。查过 GitHub 上的开源方案后，用户定了："安卓照你的建议改：Word 和 Excel 在手机上直接显示，PPT 和 .doc、.ppt 老格式还用电脑转的 PDF。"

- **Word 和 Excel 打开就显示原文件**：对话文件或电脑上的文件里，Word（.docx .docm .dotx）和 Excel（.xlsx .xlsm .xls .xlsb .csv）这几类、20MB 以内的文件，文件页先把原文件取过来，在页面里的一个网页视图里画出来。不再向电脑要 PDF：不用等电脑转，电脑上没装 Office 也能看。
  - Word 用 docx-preview：一页一页排下来，缩到屏幕宽，双指可以放大。
  - Excel 用 SheetJS：上面一排工作表名字，点了切换；每张表最多显示 2000 行、100 列，超过时写明。Excel 里隐藏的工作表不列出。
  - 做法照开源的安卓查看器 Gander（MIT 许可）：它用同样的库，在手机上离线显示 Word、Excel。
- **PowerPoint 和老格式照旧**：.pptx、.ppt、.doc、.rtf 等，以及超过 20MB 的 Word、Excel，电脑说能转（`"preview": "pdf"`）时仍用电脑转的 PDF，和 1.0.4 一样。
- **手机显示不了时**：文件坏了、加了密码这类，页面写"手机上显示不了这个文件。"。电脑能转时自动改用电脑转的 PDF；不能转时写"手机上显示不了这个文件，可保存后使用系统应用打开。"。"保存到手机""系统分享""用其他应用打开"始终拿原文件。
- **安全**：这个网页视图只读应用里自带的几个文件和这一个文件，不联网（文件里引用的网上图片也不取），没有登录信息，和应用之间没有通道；点文件里的链接用手机浏览器打开。Word 里嵌的 HTML 片段和批注不显示。
- **库的来源**（`app/src/main/assets/office/lib/`；许可证在 `assets/licenses/`，"关于遥应 → 开源组件"里列出）：
  - docx-preview 0.4.1（Apache-2.0）和 JSZip 3.10.2（MIT）从 npm 取，和 npm 记录的 sha512 一致。
  - SheetJS 社区版 0.20.3（Apache-2.0）从 SheetJS 自己的网站取（npm 上的 `xlsx` 停在 0.18.5，有已知漏洞），和 Gander 打包的那份逐字节相同。
  - SHA-256：`docx-preview.min.js` `c4a133c6…f530c2`，`jszip.min.js` `7f839b2d…d3d2c1`，`xlsx.full.min.js` `cc015130…3a6f41`。
  - 新加的文件共约 1.2MB，压缩后约 0.4MB，安装包会大这么多。
- **代码**：`PreviewUi.kt`（`phoneOffice`、`OfficePreview`）、`WorkspaceController.kt`（`file`、`convert`、`officeFailed`）、`WorkspaceUi.kt`（`FilePage`）、`assets/office/`（`word.html` `word.js` `sheet.html` `sheet.js` `office.css`）。
- **本地示例**：`发布说明.docx` 和 `预算表.xlsx` 换成真的 Word、Excel 文件（标题、列表、表格；两张工作表，合计是公式），在手机上显示；新加 `季度汇报.pptx`，约 1.5 秒后显示电脑转的一页 PDF。

## 打开对话停在最新处、Claude 的「上次操作」、Office 文件预览、长对话（2026-10-27，1.0.4）

用户 10-27 在 iPhone 上报了四个问题，安卓走的是同一套做法，这一节在安卓上改。iPhone 由另一个会话改；电脑把 Office 文件转成 PDF 的部分由主会话同时在做，安卓按约定好的接口写（见第四条）。

- **每次打开对话都停在最新处**（用户原话："保持每次点开对话都在最新的地方"）：以前打开对话时，先找这台手机记下的阅读位置，读那附近的一页，停在那一页的开头。现在不管怎么打开（列表、侧栏、新建的对话、通知、应用重新打开、重新登录），都读最新的一页，停在最底下。
  - 阅读位置不再写进手机，也不再读。数据库里存它的那张表原样留着，结构不改，以前存的不会读错。
  - 照旧的：查找消息点一条结果，读那条消息附近并停在那里；"回到最新"和"有新消息 ↓"；停在最底下时跟着新输出往下走（B09）。
  - 同一次打开里页面重新画出来时（转屏、窗口变宽变窄、从设置返回），回到刚才看的地方。这个位置只记在内存里，下一次打开不用它。
  - 代码在 `ReaderViewModel.kt`（`readChat`、`keepPlace`、`placeFor`）、`ChatUi.kt`。
- **"加载更早消息"不再往回跳**：核对时发现，点了以后页面停在按钮那一行，新读进来的消息把原来看的那条推到下面，等于往回跳了一页。现在照网页 `scroll-anchor.js`：原来在屏幕顶上的那条留在原处，更早的接在它上面。
- **Claude 的「上次操作」不再一直挂着**：Claude 卡片上的选项和按钮、"停止这一轮"、"立即补充"，发给电脑的都是一次性的 token，电脑只在给出后 120 秒内接受（`claude_control.py`）。电脑的回复如果在路上丢了，手机记成"结果待确认"；Claude 没有回执，手机以前也没有办法确认，所以「上次操作的结果还没确认」一直在，点"核对上次操作"也没有变化。现在：
  - 手机记下的这次操作多存两项：发出的时间（`at`），和这是哪一种（选项、停止、立即补充）。两项都只存在手机上，不发给电脑。
  - 点"核对上次操作"：重新读一次电脑上 Claude 的状态并显示出来，把这次操作记为已处理（下一次操作时照旧移进 `action_history`），再写读到的结果。还有在等的问题或选项，写"电脑上的 Claude 还在等你选；上次那一下可能没送到，请再选一次。"；没有了，写"电脑上已经没有在等的选项，上次的选择已处理。"停止看 Claude 是不是还在运行，立即补充看那条消息是不是还在排队，各写一句。
  - 不用点：每次读到 Claude 的状态（进入对话、每 5 秒一次的读取、发送后、操作后），发出已超过 2 分钟的、或者以前存下没有时间的，直接记为已处理，这一行就没了。
  - 不会重新发送任何东西。Codex 的回答、DeepSeek 的操作照旧核对。
  - 顺带改了两处。没打开面板时点"核对上次操作"，页面会一直处于"忙"：之后的操作都点不了，状态也不再读（没有面板时的刷新没把"忙"清掉）。回复丢了时，状态行以前写系统的英文（"timeout"），现在写"没收到电脑的回复，上次操作的结果还没确认；不会自动重试。"
  - 代码在 `WorkspaceController.kt`（`action`、`checkAction`、`claudeStateRead`、`claudePressFound`）、`ChatController.kt`（读到状态时告诉工作区：`seen`）。
- **Word、Excel、PowerPoint 在手机上直接看**：对话文件的列表或文件信息里带 `"preview": "pdf"` 时（电脑上装了对应的 Office，文件是 .doc .docx .rtf .xls .xlsx .ppt .pptx 这类），文件页向电脑要 `GET /api/file/pdf?app&id&file`，用原来看 PDF 的方式一页一页显示，放在"保存到手机""系统分享""用其他应用打开"上面。
  - 这三个按钮仍然拿原文件，转换期间就能用。
  - 等的时候写"正在用电脑上的 Office 转成 PDF…"。电脑转不了时，写电脑给的原因（`{"error": …}`，例如"没能转成 PDF：电脑上的 Excel 没有响应"），按钮照旧。
  - 和 PDF 一样最多 20MB，超过时写明可以保存后用别的应用打开。
  - 第一次转一个文件，电脑要先启动 Office，可能要 5–30 秒。所以这个请求最多等 90 秒收到第一个字节、总共 150 秒（别的请求是 30 秒和 40 秒）。之后同一个文件，电脑直接用转好的。
  - 没有 `preview` 时和以前一样。诊断测速里这个请求叫"文件预览"。
  - 代码在 `RelayApi.kt`（`filePdf`）、`WorkspaceController.kt`（`file`、`pdfFailure`）、`WorkspaceUi.kt`（`FilePage`）。
- **长对话**：iPhone 上一个很长的 DeepSeek 对话打开慢、⋯ 菜单反应慢，原因是每 2.5 秒读一次状态就把整页重画、重新解析 Markdown。安卓用 LazyColumn，只画屏幕上的几行。没有在模拟器上测（模拟器的帧数据说明不了问题），按代码查了同样几处，改了：
  - DeepSeek 的状态里有记录序号、子智能体的时间和原始收件箱，它工作时每读一次都变，手机又都不显示。现在读进来时去掉这几项，没有新东西的读取就是同一个状态，页面不动（相同的状态本来就不会让页面重画，这次加了测试）。
  - Markdown 解析结果的缓存以前最多 32 条，一页有 60 条，来回滑就要重新解析。现在按字数限制：最多 80 万字、1500 条（一页最长是 60 条 × 6000 字 = 36 万字），最久没用的先丢。
  - 时间线的每一行以前都拿着整个页面状态、对话状态和工作区状态：任何一次状态读取或者一条新消息，屏幕上每一行都要重画；每个处理步骤还要把整页走一遍，找自己属于哪一组。现在每页先算好每行要的东西，一行只拿它要显示的，回答只拿"忙不忙"；下一步框、任务卡片和 Codex 计划自己去读状态。用 Compose 编译器的报告核对过：`TimelineItem` 和 `AnswerBlock` 现在可以跳过重画。
  - 顺带：长按一条还在输出的回答，复制、分享的是它开始输出时的那几个字；现在是当时的全文。
  - 代码在 `ChatUi.kt`（`timelineRows`、`TimelineItem`、`AnswerBlock`）、`Markdown.kt`（`MarkdownCache`）、`RelayApi.kt`（`control`）。
- **本地示例**：
  - 每个对话的"对话文件"多了 `发布说明.docx`（约 1.5 秒后转好，是一页 PDF）和 `预算表.xlsx`（电脑上的 Excel 没有响应，转不了）。
  - 开发者选项 → 示例网络多了"回复丢失"：示例电脑照做（回答、批准、点 Claude 的选项），但回复回不到手机。用来在模拟器上看"核对上次操作"。读取照常。

## 推理强度的档位名字看得全（2026-10-27，1.0.3）

用户 10-27："让推理强度菜单里六个档位的名字都看得全，挑和网页、标签一致又省地方的写法"。Claude 桌面给的六个档位名字很长（"Medium Recommended""Max 3.5× or more usage"），一行分六段放不下，被截成"Med""Hig""Extr""Ultr"。

- **名字**：按模型标签上的写法（网页标签也是这样写）：Low 低、Medium 中、High 高、Extra 极高、Max 最高。对应关系来自电脑端的六个档位名（`claude_control.py` 的 `EFFORT_LABELS`）和 Claude 记录里的值（这台电脑上见到 low、medium、high、xhigh、max，Extra 就是 xhigh）。没见过的档位保留它名字的第一个词，例如 Ultracode（这台电脑上从没用过，不知道 Claude 会记成什么）。点了以后发给电脑的仍是桌面上的原名，电脑照原名去点。滑杆形式的档位，学到的名字也按同样写法。选中以后，标签和菜单写的是同一个词（选"极高"，标签变成"Opus 5.5 · 极高"）。去掉的是名字后面的"Recommended"和"3.5× or more usage"这类说明。
- **排法**：菜单里这一行（`Components.kt` 的 `MenuSegments`，Codex 和 DeepSeek 的推理强度也用它）先量每个名字的宽度：都放得下平分的宽度时照旧平分；放不下时每段按自己名字的宽度排；连这样都放不下（字号很大）才左右滑。名字一律不折行、不截断。代码在 `ComposerUi.kt`（`claudeEffortLabel`、`claudeEfforts`）和 `Components.kt`。

## 输入框：电脑上没打开的对话（2026-10-27，1.0.3）

## 0.9.1 改动（2026-10-25）

依据测试用户"咦嘻啊哈"10-25 上午对 0.9.0（9）的反馈：没装 Claude 的电脑上，顶部来源栏仍有 Claude（新建窗口里是对的）；新建对话"弹出来有点卡""退出去会卡顿"；窄屏上 DeepSeek 被压成"Deep"，也不能左右滑；侧栏 Codex 前面是通用的 `</>`，"图标调一下"。

- **来源只列这台电脑有的应用**：依据是电脑服务自己找到的桌面应用（remote.py 的 machine apps：`machines.installed_apps()`，或 remote_config.json 里的 "apps"）。网页从页面里的 `window.MACHINE.apps` 拿到它；原生不打开网页，用的是侧栏接口 `/api/chat/projects`：remote.py 只留这台电脑有的应用分组（0.20.7 起），没有会话的应用也有分组（"其他对话"总在），所以"没有会话"不会被当成"没装"。现在进入一台电脑时就读一次（以前只在打开侧栏和新建窗口时读），结果按"登录范围 + 电脑"记在手机上，下次先显示记着的，同时向电脑核对。
  - 还没读到时只显示"全部"和一行"正在读取这台电脑的应用…"；读不到时写"读不到这台电脑的应用 · 重试"，不再假装三个都有；有记着的就照常显示记着的。
  - 换电脑不沿用上一台的；选着的来源在新电脑上没有（或不知道有没有）时回到"全部"；电脑核对后发现某个应用没了，选着它的也回到"全部"并重读列表。
  - 顶部来源栏、⋯ → 列表显示 → 来源、新建窗口的来源分段、侧栏用同一份数据。新建窗口要选一个具体应用（没有"全部"）：电脑没有当前来源时换成它有的第一个，已输入的字带过去。电脑上一个应用都没有时，列表写明原因并给"重试"（同网页），新建按钮不可用。
  - 代码：`ReaderViewModel.kt`（`SourceInfo`、`loadTree`、`select`、`startNew`）、`ListUi.kt`、`WorkspaceUi.kt`。
  - 限制：电脑服务只在网页打开时重新看装了哪些应用（remote.py `_recheck_apps`），原生不打开网页，所以服务启动后才装或卸载的应用，要等电脑服务重启或有人打开一次网页，原生才看得到变化。

- **新建对话窗口**：在模拟器上录屏、取帧数据，找到三个原因（数据见下）：
  1. 窗口的玻璃底板、阴影和卡片底色画在动画图层外面，不跟着淡入淡出：打开时先冒出一块空白底板，约 0.1 秒后遮罩和内容才一下子出现；关闭时内容先淡出，空底板再停约 0.1 秒才消失。现在底板和内容在同一个动画图层里，一起淡入淡出、一起移动，下滑收起时整块跟着手指走（`Overlays.kt`）。
  2. 打开时最重的一帧（第一次排版整个窗口，模拟器上 10–30 毫秒）落在 200 毫秒的动画里，动画开头被跳过。现在窗口在第一帧排好但不显示，下一帧才开始动；列表上的"新建"直接打开窗口，最重的那帧从点按后第三帧提前到第一帧。

## 发布新版本（1.0 起）

1. 改 `app/build.gradle.kts` 的 `versionName`（`x.y.z`，不带后缀），`versionCode` 加一。
2. 在有 `%USERPROFILE%\.android\teleply-signing\` 的电脑上运行 `./scripts/release.ps1`：跑 JVM 测试，构建 release，输出 `build/Teleply-x.y.z-N.apk`，打印签名证书和 SHA-256。证书不是 `1df09ab7…b2e22946` 时脚本报错停下。
3. 在仓库根目录运行 `.toolchain\release-venv\Scripts\python.exe deploy\updates\publish.py android apps\android\build\Teleply-x.y.z-N.apk --notes-file 说明.txt`（见 `deploy/updates/README.md`）：它给 `android-update.json` 签名，域名绑好以后还会传到阿里云。再把 APK、`android-update.json`、`android-update.json.sig` 附到本仓库的 GitHub Release `android-vx.y.z`，文件名不改。1.0.3 起应用先看阿里云，再看 GitHub，只认签过名的清单；1.0.2 及以前只认 GitHub 上的 APK。手机上的应用每天看一次，也可以在设置里点"检查更新"。
4. `teleply-signing` 文件夹一旦丢失，就发不了能覆盖安装的更新，所有人得卸载重装；一旦泄露，别人能做出能覆盖安装的假遥应。另外离线备份一份，不要提交进仓库，也不要发给别人。

## 阶段4实施方案与验收条件（2026-10-24，先于实现记录）

依据 Android Jetpack Compose 设计规范第3、4.4、5和7—9节，阶段4范围是无障碍、系统分享/预览、通知与语音权限、前后台恢复、窗口适配和性能。保留阶段3功能与账号/电脑/来源/会话隔离；Claude／DeepSeek真实交互继续待验收。本次不改变服务端、不引入FCM或新云端服务，不涉及生产签名、公开发布或旧包迁移。

1. **无障碍与输入（T03/T12/T13）**：消息/代码/表格标题具备语义，单选/多选整行可操作且标签明确；重复“复制/移除”动作标明对象；流式正文不逐token播报。保持48dp触摸目标，2倍文字、横屏与短窗口下关键操作可滚动到达；键盘优先返回，菜单/详情其次，草稿不丢。采用系统动效尺度，不增加强制动画。Compose语义检查不能替代TalkBack真人阅读、焦点顺序与中文候选输入验收。
2. **系统分享与外部预览（B01/B12/B16，T08/T10）**：在明确授权的当前文件详情增加系统“分享/用其他应用打开”，以流式下载取得具体文件，写入独立应用私有分享缓存；FileProvider只暴露该子目录，给接收方临时只读content URI，不传Cookie、服务地址或本地路径，不执行HTML脚本。切换身份/会话取消旧结果；只显示“已打开系统选择器”，不虚报分享完成。保存继续走系统文档创建器。过期分享缓存受限清理，分享中的文件不立即删除。
3. **通知与跳转（B01/B11，T11/T12）**：默认关闭，由用户为当前会话开启；Android13+在该动作中请求通知权限，拒绝不影响阅读。采用平台JobScheduler按系统最低周期进行有网络约束的只读状态检查，明确不是实时推送，Doze/省电/强制停止可延迟或停止。只关注一个明确会话，检查前重新核对服务、登录作用域和设备归属；失效或离线不猜测完成。状态变化去重，通知不展示正文/账号/客户标题。点击通知使用本机生成的不可猜测目标标记，经当前账号重新核对后导航，不从Intent接收凭据或任意URL；不执行发送/批准。前台正在阅读同一会话时不重复通知。开机恢复只恢复已启用的系统任务，不承诺后台无限保活。
4. **语音输入（T03/T08/T11）**：仅显式点按后请求RECORD_AUDIO；优先设备具备的本机识别，否则明确系统识别可能联网。无识别服务、拒绝权限、取消、空结果都有说明；结果只加入原会话草稿，绝不自动发送，不覆盖后续新输入，不跨账号/电脑/会话回填。退后台/切换/销毁时取消并销毁识别器，不保留录音文件，不调用服务端语音服务或上传整段音频。真实录音/识别质量需用户配合，固定回调测试只证明状态处理。
5. **窗口、恢复与性能（B09/B11，T02/T04/T11/T13）**：宽窗口提供列表/详情，按可用宽高和字体缩放回退单栏；不按设备名称判断，不因旋转、分屏或宽度变化复制会话/请求。列表有界分页，读取锚点与展开状态尽量保持；优化Markdown重复解析与可见内容渲染，避免流式更新牵动整个历史。验证前后台、进程恢复、旋转/宽窗口与大字。使用固定脱敏长会话记录模拟器设备、数据规模和测量方式；不把debug模拟器的数字或静态截图当成真机帧率承诺。
6. **验收与人工配合**：先做受影响JVM/Compose、权限/通知身份/共享路径/语音竞态检查，再构建、lint与模拟器仪器测试；不清除现有登录数据。分享/语音/后台通知只运行固定场景或用户明确开启的对象，真实工作会话不产生写动作。真机安装、TalkBack、真实中文输入、锁屏/省电通知、语音质量及真实性能需人工验收，届时提供具体步骤。没有真机时只记录已测数据，真机性能标为“待测”，不作通过或不通过判断；Claude／DeepSeek真实交互不在本轮扩展。结果仅回写本README，交付独立0.4.0预览APK和必要固定示例截图，不生成额外报告。

平台依据：[JobScheduler周期与开机保留](https://developer.android.com/reference/android/app/job/JobInfo.Builder)、[SpeechRecognizer生命周期与权限](https://developer.android.com/reference/android/speech/SpeechRecognizer)、[FileProvider只读授权](https://developer.android.com/reference/androidx/core/content/FileProvider)。本节为实施前方案，不表示已通过验收。

## 数据与边界

`ReaderViewModel` 用 StateFlow 管理导航、请求代次、身份和恢复；`ChatController` 管理草稿、提交与生命周期订阅，`StreamReducer` 核对每条连接的身份和序号。切换请求会取消协程，并拒绝迟到结果。`RelayApi` 使用 OkHttp 和已锁定的 okhttp-sse；所有电脑业务 URL 均显式绑定 `/d/{deviceId}/`。后台停止订阅，回前台先核对状态和原回执，再取新快照；不重放写请求。

服务地址必须为 HTTPS 根地址；POST Origin 与规范化根地址一致；系统 TLS 验证保持开启；禁用所有自动重定向。只接收安全、HttpOnly、host-only、根路径的 `__Host-ar_account` Cookie，通过 Android Keystore AES-GCM 加密并绑定 origin 保存。密码只用于一次登录，不持久化、不日志输出、不读取旧 WebView Cookie。备份和设备迁移排除应用数据。

DataStore 保存外观、服务配置和恢复 ID，不存密码、正文或对话标题；Room v3 按登录作用域 / 电脑 / 来源 / 会话隔离锚点（2026-10-27 起不再写入和读取，表照旧保留）、草稿和提交快照，并用 interaction_draft 保存附件元数据、引用、回答和创建请求。v1→v2→v3显式迁移保留既有数据；提交快照先落盘，才执行一次 POST。正文历史仅留内存，草稿和提交快照留在禁止备份的应用私有存储。UI 的 TextFieldValue 保留光标和中文组合区，逐字输入不由服务状态回写；仅加载、恢复或提交清空时改变外部文本版本。IME可见时系统返回只收起键盘。

当前 `/account/state` 无稳定账号 ID；登录过期时保留阅读快照。重新登录后，只有原电脑 ID 仍在该账号拥有的设备列表中才恢复原作用域；否则清除旧视图并分配新作用域。进程重启后先验证账号与设备，再读取最新一页（2026-10-27 起每次打开都停在最新处，不再回到上次的阅读位置）。离线电脑和 `409 device_offline` 明确处理。

Markdown 由 CommonMark Java 0.24.0（BSD-2-Clause）解析成原生段落、标题、列表、引用、代码、表格和链接。宽代码/表格局部滚动；复制原始文本；截断消息必须先展开完整内容。HTML 文件在应用内的网页视图里按网页打开（0.7起，用户决定）：脚本和网上资源照常加载，同目录文件只取这个对话列出的；不带应用的 Cookie、没有原生桥、不能读手机文件，点链接用系统浏览器打开。授权当前文件支持文本、图片和PDF原生预览、系统保存；本轮差异只读取来源已完成的变更记录。手机文件先分块读取到应用临时缓存再流式上传，保存分块下载，取消或切换身份终止旧传输；临时上传文件在结束/取消时删除。单图20MB、最多5张/合计50MB、文件上传100MB沿用服务约束；本预览版下载上限100MB，图片/PDF内嵌预览上限20MB（更大文件可保存），文本预览遵守服务1MB上限。AndroidX、Kotlin、OkHttp 采用 Apache-2.0。液态玻璃代码移植自 Kyant0/AndroidLiquidGlass（Backdrop，Apache-2.0），见 `third_party/backdrop/`。
